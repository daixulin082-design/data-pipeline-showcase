> 一套把「网页/接口」变成「干净结构化表格」的完整工程方案
> 覆盖 40+ 站点，累计处理 4 万+ 条结构化数据

---

## 一、这套流水线解决什么问题

大多数数据采集需求，客户真正要的不是「爬虫」，是**一份能直接拿去用的表**。

所以完整链路是三层：

```
采集层  →  清洗层  →  交付层
（拿到原始数据） （去重/抽字段/去噪） （Excel / CSV / 静态站 / API）
```

三者里，**采集只占 20% 工作量，清洗和交付占 80%**。

## 四、三个核心技术点

### 1. 接口优先，HTML 兜底

打开 F12 → Network → XHR，先确认数据是从哪来的：

| 站点类型 | 数据来源 | 稳定性 |
|---|---|---|
| 传统 CMS | 服务端渲染 HTML | 低（改版即失效） |
| Discuz 论坛 | `/api/mobile/index.php` JSON | 高 |
| FastAdmin | 服务端渲染 + Cookie 鉴权 | 中 |
| SPA | `/api/xxx/list` JSON | 高 |

JSON 接口相比 HTML 解析：**稳定 10 倍、快 3 倍、字段干净**。

### 2. 限流不是「到底了」

新手最常见的 bug：把 429/403 当成「没有下一页」，导致采集中途静默停止。

```python
if r.status in (429, 403):
    time.sleep(4 + attempt * 2)   # 指数退避
    continue
```

配合 `0.75s/页` 的请求间隔 + 连接复用，可以长时间稳定运行。

### 3. 去重按业务指纹，不按文本相似度

同一实体重复发布 3–5 次，标题不同但联系方式一致：

```python
sig = (city,) + tuple(sorted(contact.items()))
```

准确率从 68%（文本相似度）提升到 99%。
